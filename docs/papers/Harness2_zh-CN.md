## 摘要

大语言模型（LLM）智能体的能力不仅取决于底层模型，也取决于其执行装具（execution harness）。递归自改进（Recursive Self-Improvement, RSI）为自动演化这些装具提供了有前景的路径。然而，在开放世界中部署 RSI 仍面临两个关键挑战。第一，开放世界任务通常在装具设计阶段未见过，测试时也是新颖任务，因而没有可用于可靠引导在线装具编辑的真值校验器。第二，RSI 过程高度任务特异，难以泛化到新场景。

我们提出 **Harness 2**：一个即插即用的递归式智能体装具优化框架，通过两层相连的递归解决上述问题。

- **任务级递归（Task-level recursion）** 使用对比式「提出—探测—组合」（Propose–Probe–Compose）步骤，在没有真值校验器的情况下可靠地引导编辑；并可进一步通过并行或串行递归扩展。
- **装具化级递归（Harnessing-level recursion）** 再从这些编辑中抽取经验，更新持续改进装具，使智能体更好地适应未来任务。

在三个专业基准与四种模型—装具配置上，单步改进即可使 GLM-5 与 Gemini 3.5 Flash 相对其基线装具持续提升：WorkBuddy-Bench 最高 +11.5 分，JobBench 最高 +4.5 分，LAB 最高 +11.8 个百分点；增大任务级递归预算可进一步提升。

## 1 引言

LLM 智能体的效果不仅取决于底层模型，也取决于其**装具（harness）**：模型执行任务时使用的提示、记忆、技能、工具与编排（OpenAI, 2025; SST, 2024; Weng, 2026）。即便同一强模型，在不同装具下表现也可能大相径庭（Team et al., 2026）。随着智能体从编程扩展到办公流程以及法律等高风险领域，装具设计必须容纳日益多样的任务与运行要求。手工设计与迭代装具需要反复工程投入，因此催生了装具设计上的递归自改进（Lee et al., 2026b; Lin et al., 2026; Qian et al., 2026; Weng, 2026; Meng et al., 2026）。RSI 追求「AI 改进 AI」：系统自主对自己做持久修改，而这些修改又进一步影响后续改进如何生成、评估与保留（Duan et al., 2026）。

早期装具 RSI 方法（Lee et al., 2026b; Lin et al., 2026）主要在固定训练任务、单元测试或验证反馈上优化候选组件，并在部署前选出最佳配置。但事先选定的静态装具往往难以泛化到开放世界中多样、不可预测的环境（Wang et al., 2026a）——在该动态设定中，智能体持续遭遇需求多样且不断演化的新任务。为此，研究者将装具 RSI 推向开放世界，使系统能动态适应新到达的任务：常见做法是递归改进当前任务的装具（Lee et al., 2026a; Wang et al., 2026a），或把成功的执行装具带到后续任务批次（Nie et al., 2026b）。

然而，开放世界装具演化仍有两个相连挑战：

1. **任务通常缺乏真值标签或可靠校验器。** 现有方法依赖代理信号、假定真值答案或成对输出判断（Lee et al., 2026a; Nie et al., 2026b; Liu et al., 2026），如何安全地用不完美的执行证据引导装具变更仍很困难。
2. **对一个任务改进装具，并不会自动改进下一任务的精炼方式。** 任务特异编辑在需求变化时会失效；直接继承高度定制的执行装具，在任务分布漂移时反而可能造成嘈杂的递归改进。但精炼过程本身会产出高度可复用经验：如何诊断弱点、测试了哪些变更、执行揭示了什么。因此，**改进过程本身必须成为学习来源**，使系统递归升级自己的精炼机制。

为此，我们提出 **Harness 2**：面向开放世界的即插即用递归智能体装具优化框架。「装具化（harnessing）」指优化冻结基座模型周围的运行时脚手架，使其能作为自主智能体行动。Harness 2 既改进当前任务的装具，也从该过程抽取经验以指导未来装具化，并通过两层耦合递归实现：

1. **任务级递归**：精炼当前任务的执行装具。为克服缺少真值反馈，我们引入对比式 Propose–Probe–Compose：提出装具编辑、在匹配条件下测试效果，并基于行为对比组合得到支持的变更。在此基础上，并行递归同时探索多个候选并从执行证据组合变更；串行递归则迭代构建连续修订。
2. **装具化级递归**：用任务级探索结果更新持续改进装具。不继承上一执行装具，而是选择性地保留可复用组件及「何时/为何有效」的经验，指导后续提案与组合。

我们在 WorkBuddy-Bench、JobBench 与 Harvey 的 Legal Agent Benchmark（Team et al., 2026; Li et al., 2026; Harvey AI, 2026）上，跨四种执行器—装具配置评估 Harness 2。一步对比改进即可在全部配置、三个基准上提升表现：WorkBuddy-Bench 最高 +11.5，JobBench 最高 +4.5，LAB Partial 通过率最高 +11.8 个百分点。并行递归可再带来 WorkBuddy-Bench 最高 +3.9、JobBench +4.2、LAB Partial +6.7 个百分点（图 1）；预算研究表明并行与串行递归都能继续增益。重要的是，任务级探索也惠及后续装具化：更大递归预算积累的库即便不再探测也能支持更强后续编辑；从 JobBench 迁移的库也能提升 WorkBuddy-Bench（图 7）。

**贡献三点：**

1. **递归智能体装具化**：Harness 2 精炼当前执行装具，并从精炼过程学习以指导未来装具化。
2. **无需真值反馈的任务级递归**：提出对比式 Propose–Probe–Compose，支持并行与串行递归。
3. **实验结果**：在三个基准与四种执行器—装具配置上展示一致增益，包括同一模型兼任执行器与编辑器的设定。

## 2 Harness 2

我们先定义递归智能体装具化及其开放世界设定（§2.1），再给出精炼执行装具的任务级递归（§2.2），以及跨任务更新改进装具的装具化级递归（§2.3）。

### 2.1 递归智能体装具化

**装具配置与设定。** 设 \(\mathcal{M}\) 为参数冻结的模型。装具 \(\mathcal{H}=(c^{1},\ldots,c^{K})\) 由 \(K\) 个可编辑组件组成。它与 \(\mathcal{M}\) 组合形成智能体 \(\mathcal{A}(\cdot;\mathcal{M},\mathcal{H})\)，且不改变模型权重（Lee et al., 2026b; Huang et al., 2026b; Qian et al., 2026）。对执行装具，我们采用 AHE（Lin et al., 2026）的文件级分解并扩展一个组件，暴露 \(K=8\) 个组件：系统提示、护栏、记忆、技能、工具指引、脚本、子智能体，以及中间件插件。每个组件以文件形式挂载到运行时。图 2 展示其运行时角色；附录 D.3 表 5 给出文件、激活方式与定义。我们研究在 \(N\) 个开放世界任务流 \(q_1,\ldots,q_N\) 上的装具演化，**没有真值答案或带标签的验证反馈**。每个任务从公共执行装具 \(\mathcal{H}_0\) 起步；管线可在有界预算内重跑当前任务，再返回最终交付物。

**递归智能体装具化。** RSI 指 AI 系统能把执行结果与内部反思转化为对自身的持久修改，从而影响后续改进的生成、评估与保留（Duan et al., 2026）。修改对象可以是模型权重（自奖励语言模型，Yuan et al., 2024）、改进程序（STOP，Zelikman et al., 2024）或智能体代码（Darwin Gödel Machine，Zhang et al., 2026b）。智能体装具也可以是此类对象：它是使基座模型成为自主智能体的外围系统（\(\text{Agent}=\text{Model}+\text{Harness}\)），且不改权重（Weng, 2026）。优化这一层的过程称为**装具化（harnessing）**。我们不仅在固定改进程序下修订执行装具，也更新引导未来修订的装具：

> 递归智能体装具化将「模型—装具」视角从「执行任务的智能体」扩展到「也学习如何改进装具的智能体」：执行装具是被改进对象，改进装具是改进机制。

在 Harness 2 中（图 3），执行装具针对当前任务精炼，持续改进装具则跨任务支持精炼。改进装具在任务级递归期间保持固定，之后通过其**装具改进库**更新。该库保留被采纳的装具及其精炼经验，供后续提案与组合复用与适配。

### 2.2 任务级递归

任务级递归旨在改进当前任务的执行装具。开放世界设定的难点是：**在没有真值反馈时如何引导修订**。我们因此引入对比式改进步骤：提出变更、执行并考察行为后果；并行与串行递归再基于生成的装具与执行证据进一步精炼。

#### 2.2.1 对比式改进步骤

对比式一步包含 **Propose（提出）、Probe（探测）、Compose（组合）**。令 \(e=(\tau,y)\) 表示执行记录（轨迹 \(\tau\) 与交付物 \(y\)）。该步对当前执行装具 \(\mathcal{H}\) 与可用的任务局部执行/改进历史 \(\mathcal{E}\) 施加改进操作 \(\Phi\)：

\[
(\mathcal{H}',e',\xi)=\Phi(q_t,\mathcal{H},\mathcal{E};\mathcal{R}_t). \tag{1}
\]

返回后继装具 \(\mathcal{H}'\)、其执行记录 \(e'\)，以及步骤记录 \(\xi\)（含参考执行、候选装具与探测、组合决策、后继执行）。模型与环境不变故省略；改进装具 \(\mathcal{R}_t\) 在任务全程固定。

**Propose。** 管线先取得参考执行 \(e^0\sim\mathcal{A}(q_t;\mathcal{M},\mathcal{H})\)。参考揭示装具**如何行为**，而非交付物是否正确。在任务、当前装具、参考、更早历史以及 \(\mathcal{R}_t\) 中库的条件下，管线提出两类候选：

- **不变性候选（invariant）**：针对可能跨领域复现的智能体缺陷，如规划、工具使用、上下文管理或委派；
- **领域特异候选（domain-specific）**：针对当前领域/环境的知识、流程与约束。

每个候选是通过编辑当前装具组件文件得到的可执行装具。提案可复用或适配库中组件，但任务特异事实必须对照当前任务证据核验。

**Probe。** 每个候选装具在相同任务、匹配的模型与环境配置下执行。将其轨迹与交付物与参考执行对比，得到**行为对比**：证据表明编辑是否缓解目标缺陷、相关行为是否不变，或是否引入回归。这些对比用于后续组合，**而非验证任务正确性**——执行随机性与共享模型偏差会限制证据可靠性。

**Compose。** 管线读取参考、候选装具、相对当前装具的 diff，以及所有任务局部执行证据，形成后继 \(\mathcal{H}'\)。组合是选择性的：可合并受支持变更、修订冲突编辑、采纳某一候选，或保留当前装具。每项决策绑定具体观察，而非假定分数提升。组合后的装具再执行得到 \(e'\)，决策与证据记入 \(\xi\)。

#### 2.2.2 并行与串行递归

在对比式改进步骤之上，我们引入两种任务级递归（图 4）：

- **并行递归**：从多个候选装具及其执行组合精炼；
- **串行递归**：把精炼后的装具与执行证据带入后续步骤。

正整数 \(k\) 控制探索预算：并行时每个范围 \(k\) 个候选与 \(k\) 次组合；串行时链式 \(k\) 步。改进装具 \(\mathcal{R}_t\) 全程固定。

**并行递归。** 遵循 RSA（Venkatraman et al., 2025）的聚合原则，但作用于可执行装具及其行为后果，而非推理输出。管线收集当前装具 \(\mathcal{H}\) 的 \(k\) 次参考执行，再独立提出并探测 \(k\) 个不变性与 \(k\) 个领域特异候选。令 \(\mathcal{B}\) 为参考执行，\(\mathcal{P}\) 为候选装具及其执行记录池。\(k\) 个独立组合会话各自接收完整池：

\[
\mathcal{H}'_j=\textsc{Compose}_j(q_t,\mathcal{H},\mathcal{B},\mathcal{P};\mathcal{R}_t),\qquad j=1,\ldots,k. \tag{2}
\]

每个会话选择性组合或修订受支持编辑，得到后继 \(\mathcal{H}'_j\) 并执行。我们的实现做一次群体更新；\(k\) 控制宽度而非深度。

**串行递归。** 将迭代自精炼（Madaan et al., 2023）应用于执行装具。从 \(\mathcal{H}^{(0)}=\mathcal{H}_0\) 起，链式 \(k\) 个对比步骤，每步条件于前一装具与累积执行历史 \(\mathcal{E}^{(r-1)}\)：

\[
(\mathcal{H}^{(r)},e^{(r)},\xi^{(r)})=\Phi(q_t,\mathcal{H}^{(r-1)},\mathcal{E}^{(r-1)};\mathcal{R}_t),\qquad r=1,\ldots,k. \tag{3}
\]

初始历史含 \(k\) 次基线执行，每步后用 \(\xi^{(r)}\) 扩展。后续步骤可用当前与先前证据保留、修订或纠正更早变更。

**最终选择。** 当 \(k>1\) 时，智能体式选择器对比匿名交付物与任务请求及源材料，返回既有输出，且无法访问其来源装具或合成新内容。对应装具记为 \(\mathcal{H}_t^{\star}\)（星号表示采纳，而非已验证最优）。选择不加装具修订。\(k=1\) 时两种形式都退化为基本对比步骤并跳过选择。附录 H 给出阶段提示词。

### 2.3 装具化级递归

装具化级递归用精炼当前执行装具的经验改进未来装具化。每任务后，管线更新改进装具 \(\mathcal{R}_t\) 中的库，使被采纳装具及其精炼经验对后续任务可用。

**反思改进过程。** 返回交付物后，管线审视完整改进记录 \(\mathcal{D}_t\)（参考执行、候选与探测、组合决策、选定结果）。反思抽取：哪些变更解决了观察到的缺陷、在何种条件下、带来何种后果。仅当有执行对比支持时才保留经验；**仅靠选择输出不能确立可迁移性**。

**更新改进装具。** 管线将被采纳装具 \(\mathcal{H}_t^{\star}\) 与受支持经验写入装具改进库：

\[
\mathcal{R}_{t+1}=\textsc{Update}(\mathcal{R}_t,\mathcal{H}_t^{\star},\mathcal{D}_t). \tag{4}
\]

每条库条目含可执行装具与 `EXPERIENCE.md`（适用情境、经验与支持证据）；索引使后续会话可按需查阅。证据不足时不新增经验条目。

**在后续改进中复用。** 下一任务仍从公共执行装具 \(\mathcal{H}_0\) 起步，但精炼由更新后的 \(\mathcal{R}_{t+1}\) 引导。更早组件经 Propose 选择性复用/适配，而非自动继承；累积经验也指导 Probe 与 Compose。模型权重、阶段指令与决策规则固定，库则演化。增大任务级探索会产出更多执行证据与组合决策，供未来装具化学习。图 7 用不同递归预算下积累的库检验这一联系。

## 3 实验

### 3.1 实验设置

**基准。** 在三个不同专业领域基准上评估：

- **WorkBuddy-Bench**（Team et al., 2026）：办公式交付物，含 Code / Web / Office 三域；
- **JobBench**（Li et al., 2026）：端到端专业工作任务，执行较长；
- **LAB**（Harvey AI, 2026）：法律工作基准；按协议报告 Partial（按标准通过率）。

主表报告三次运行的均值与标准差（每次任务顺序打乱）；「+ Recursion」行报告均值变化。同时报告 #Steps（每任务执行步数），以便对照分数变化与所需执行量。更多细节见附录 B。

**基线。**

| 基线 | 说明 |
| --- | --- |
| Base harness | 初始装具不变 |
| ReasoningBank | 装具固定，从过去轨迹检索蒸馏策略回上下文 |
| Meta-Harness† | 离线在训练划分上搜索装具代码并部署最优 |
| Harness Scaling | 对每个评估实例用额外推理预算修订装具，实例间不携带状态 |

**实现细节。** Gemini 3.5 Flash 与 GLM-5 作为冻结执行器，分别置于现成 OpenCode 与 Codex 装具下。同一改进步骤应用于每个基准的四种配置。默认装具编辑器为 Claude Opus 4.8（OpenCode）。主表报告 \(k=1\) 的单步 Harness 2；「+ Recursion」为 \(k=5\) 并行任务级递归。装具改进库在每个基准流上从空开始，每任务后更新。

## 5 相关工作

**递归自改进。** RSI 设想 AI 参与自身发展，能力改进使进一步改进成为可能，目标是让进步可累积（Weng, 2026; Duan et al., 2026）。改进对象可以是权重、程序或冻结模型周围的装具。早期方法通过自反馈精炼输出或保留反思（Madaan et al., 2023; Shinn et al., 2023）。STOP 递归改写代码改进程序；Darwin Gödel Machine 通过基准评估变体演化智能体代码；Hyperagents 使元级修改程序可编辑；MetaSkill-Evolve 与 MCE 共同演化任务产物与技能。这些系统多依赖效用/基准/验证引导优化。Harness 2 则研究：**在无真值反馈、不重访已完成任务的部署任务流上，装具改进如何跨任务累积**。

**装具优化与演化。** 自动优化已从提示、工作流、记忆与技能扩展到完整可执行装具。离线方法用可复用训练任务与评估反馈搜索候选；测试时方法则用执行反馈精炼任务特异装具，或跨无标签批次携带演化装具。Harness 2 将对比式任务级精炼与改进装具更新结合在**一遍部署流**中，无需真值监督或模型更新。表 4（附录 A）总结区分。

## 6 结论

我们提出 Harness 2：递归智能体装具化框架——精炼当前执行装具，并从该过程学习以指导未来装具化。任务级递归基于对比式改进步骤，通过并行组合或串行精炼展开；装具化级递归用被采纳装具及其精炼经验更新改进装具。跨三个专业基准、两种执行器与两种初始装具的实验显示相对基线配置的一致增益。消融与迁移研究进一步证明范围化提案、组合与累积装具化经验的价值。这些发现支持：**递归装具化可将任务特异精炼转化为可复用基础，用于开放世界任务上的在线测试时适应。**

## 附录 A 装具改进方法比较

### A.1 比较维度

表 4 比较六维：**Object（对象）、Stage（阶段）、Label（标签）、Streaming（流式）、Scaling（扩展）、Improver Update（改进器更新）**。

- **Object**：从提示/工作流到记忆/技能，再到完整可执行装具。Harness 2 区分**执行装具**与**改进装具**。
- **Stage**：离线方法在固定基准任务上反复评估候选；Harness 2 从空库起步，从到达的部署任务学习。
- **Label**：Harness 2 使用行为对比，**无即时或延迟正确性标签**；基准分数仅用于评估。
- **Streaming**：Harness 2 逐任务处理：未来请求不可见、已完成任务不重放，当前任务可在预算内重复执行。
- **Scaling**：Harness 2 通过并行/串行递归扩展装具精炼，并考察对未来装具化的益处。
- **Improver Update**：每任务后用被采纳装具与候选执行/组合经验更新改进装具；模型权重与改进算法固定。

**表 4 要点：** 多数离线方法有 Label、无 Streaming；ReasoningBank / Harness Scaling 等在线且无 Label，但 Improver Update 较弱；**Harness 2 同时具备 Online + 无 Label + Streaming + Scaling + Improver Update**。

## 附录 F 局限

1. **递归精炼成本**：需要额外执行与编辑器会话；增大预算增加推理成本。并行可降延迟，但不能消除额外计算。

## 附录 H 提示词（中文说明）

原文附录 H 给出改进器各阶段的完整英文系统提示（Harness Editor、Composer、最终选择、Experience Reflector）。会话均为智能体式：工作区 `context/` 目录持有任务、当前装具、完整轨迹、交付物与库；提示说明如何使用证据而非内联证据。提示中不出现量规、分数或评分器。

### H.1 装具编辑器 — 不变性维度（INV）

**职责**：如何让智能体**工作**（流程、工具使用、完成），而非题材知识。将失败匹配到最便宜有效组件：

| 失败类型 | 建议杠杆 |
| --- | --- |
| 工具错误 | 区分坏输入/超时/缺能力/权限/未读输出；给出有界回退与停止条件 |
| 机械重复 | 用 `scripts/<name>.py` 做确定性抽取/转换/检查 |
| 触发式工作流 | 按需 skill + 常开文本中的触发句 |
| 被忽略的不变式 | 仅在反复证据表明散文被跳过时，才用防御性 `plugin` 钩子 |
| 普通排序 | 优先简洁常开指引 |

强调：把工作区已验证事实写入组件；流程写成域级可复用；从库复制组件时必须对照当前证据重核验工作区事实。编辑必须追溯到轨迹中的具体时刻。无量规/答案键。优先 SKILL → SCRIPT → SUBAGENT → PLUGIN → 常开文本。三条会使整提案作废的规则：技能必须有触发行；常开文本禁止模板花括号；点名的脚本必须存在。

### H.2 装具编辑器 — 领域维度（DOM）

**职责**：从业者知识——交付物、受众与决策、控制源、所需结构、一致性关系、专家遗漏。转化为可检查规则（分析动作、产物契约、决策规则、编码形式）。技能是有可识别触发的领域知识的默认载体。禁止编造权威/标识符；不把本案事实写入持久记忆。不诊断命令/重试/脚本/钩子（那是 INV 候选的职责）。

### H.3 装具组合器（并行）

从 \(k\) 次基线 rollout 与 \(2k\) 个候选（\(k\) INV + \(k\) DOM）各一次 rollout 的证据中，组合**一个**最终装具：合并跨候选、整案采纳一个、或 KEEP_BASE。基线集中重复失败才是强信号；单次候选 rollout 证据弱。若与某编辑相关的 rollout 未产出任何东西，视为不安全除非证据压倒性。笔记格式：`kept|revised|dropped -> <编辑> -> <证据时刻>`。

### H.4 串行组合器差异

组成第 \(t/k\) 个检查点；证据含本轮候选与所有更早轮。可跨轮合并（含早前拒绝的候选）、原样复现更早检查点、或采纳本轮最佳。KEEP_BASE 指保留**当前检查点**，而非恢复原始装具。

### H.5 最终选择器

在 \(n\) 个匿名候选交付物中选一个提交。故意不知哪些来自未改装具。决策顺序：交付完整性 → 符合请求形状 → 相对源材料保真 → 内部一致 → 可操作性 → 完成度。长度与润色本身不是优点。

### H.6 经验反思器

阅读完整改进记录，为库写两类内容：(1) 每个变更组件的编辑行（helped / hurt / no observed effect / confounded）；(2) 至多一条可迁移经验（cue / lesson / evidence / confidence）。仅选择交付物不能确立编辑有帮助或可迁移；证据不足则写 `NO_ENTRY`。
